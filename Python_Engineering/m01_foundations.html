Дълбоки Основи на Python & CPython Обекти

Подробен поглед върху вътрешната структура на обектите, оптимизациите на паметта и представянето на типовете данни в CPython.

1.1. Всичко е Обект: CPython `PyObject` Структура

В CPython абсолютно всяка променлива, функция, клас и тип данни е C структура, разположена в dynamic memory (heap). Базовата дефиниция за всеки обект в C изглежда така:

cpython/Include/object.h (C Source)
typedef struct _object {
    _PyObject_HEAD_EXTRA  // Двойно свързан списък за GC дебъгинг
    Py_ssize_t ob_refcnt;  // Брой референции към обекта
    struct _typeobject *ob_type; // Указател към типа на обекта
} PyObject;

За обекти с променлив размер (като list, str, tuple) се използва PyVarObject, добавящ полето ob_size:

PyVarObject Layout
typedef struct {
    PyObject ob_base;
    Py_ssize_t ob_size; /* Брой елементи в контейнера */
} PyVarObject;

1.2. Mutability (Променливост) и Идентичност (`id`)

Идентичността на обекта се определя от неговата физическа адресна позиция в паметта. В CPython id(obj) връща именно числовия адрес на PyObject в RAM.

Тип Данни Променливост (Mutable) Промяна на стойността Памет Адрес (`id`)
int, float, str, tuple Immutable Създава нов обект в паметта Променя се
list, dict, set, bytearray Mutable Модифицира C структурата in-place Остава НЕпроменен

1.3. Small Integer Caching & Arbitrary Precision Integers

CPython алокира предварително при стартиране на процеса целите числа в диапазона от -5 до 256 в статичен масив small_ints. Всички променливи с тези стойности сочат към един и същ адрес.

integer_cache.py
a = 250
b = 250
print(a is b)  # True -> Сочат към един и същ PyObject в static memory

x = 257
y = 257
print(x is y)  # False -> Два отделни PyObject-а в Heap-а

За цели числа извън този диапазон CPython използва система за произволна точност (Arbitrary Precision Arithmetic), разделяйки числото на цифри в масив ob_digit.

1.4. String Interning и PEP 393 (Compact Unicode)

За да спести памет и да ускори сравняването на стрингове (напр. имена на променливи и речници), CPython прилага **String Interning**. Всички идентификатори се интернират автоматично.

От Python 3.3 (PEP 393) стринговете използват гъвкава вътрешна кодировка според най-големия Unicode символ:

  • Latin-1 (PyASCIIObject): 1 байт на символ (ако съдържа само ASCII).
  • UCS-2: 2 байта на символ (ако съдържа кирилица или гръцки).
  • UCS-4: 4 байта на символ (ако съдържа Emoji или редки йероглифи).

1.5. Компактни Речници (Compact Dictionaries - PEP 468)

От Python 3.6+ речниците запазват реда на вкарване и изразходват с 30–40% по-малко памет благодарение на разделянето на разпръснатия Hash Table от действителния масив с данни.

Dict Layout Architecture
# Стар модел (преди 3.6): 24 байта на празен слот
entries = [
    [hash0, key0, value0],
    [None,  None, None],
    [hash1, key1, value1]
]

# Компактен модел (3.6+):
indices = [0, None, 1]  # Тънък масив от байтове
entries = [             # Плътен масив само със записани елементи
    [hash0, key0, value0],
    [hash1, key1, value1]
]

1.6. Оптимизация на Паметта: Lists vs Tuples

Докато list е динамичен масив, който заделя допълнителен капацитет (over-allocation) за постигане на $O(1)$ при append(), tuple е статичен и фиксиран по размер.

memory_footprint.py
import sys

t = (1, 2, 3, 4, 5)
l = [1, 2, 3, 4, 5]

print(f"Tuple размер: {sys.getsizeof(t)} bytes") # ~80 bytes
print(f"List размер:  {sys.getsizeof(l)} bytes") # ~104 bytes (поради over-allocation)

1.7. Shallow vs Deep Copy: Механика в Паметта

При плитка копираща операция (copy.copy()) се създава нов контейнерен обект, но вътрешните референции сочат към същите обекти в паметта. При дълбоко копиране (copy.deepcopy()) рекурсивно се копират всички съдържащи се обекти.

1.8. Референтен Брояч (Reference Counting Basics)

Всеки обект съдържа ob_refcnt. Всяко присвояване увеличава брояча, а всяко изтриване с del или излизане от scope го намалява. Когато ob_refcnt == 0, CPython незабавно освобождава паметта.

1.9. Практически Казус: Оптимизация на 1 Милион Записа

Проблем: Зареждане на 1 000 000 координатни точки {"x": int, "y": int} изразходва над 180MB RAM поради накладните разходи на речниците.

Решение: Използване на __slots__ в персонализиран клас или namedtuple намалява разхода на памет с над 60%.

case_study_slots.py
import sys

class PointDict:
    def __init__(self, x, y):
        self.x = x
        self.y = y

class PointSlots:
    __slots__ = ('x', 'y')  # Премахва __dict__ от всеки екземпляр
    def __init__(self, x, y):
        self.x = x
        self.y = y

p1 = PointDict(10, 20)
p2 = PointSlots(10, 20)

print(f"Обикновен обект (с dict): {sys.getsizeof(p1) + sys.getsizeof(p1.__dict__)} bytes")
print(f"Оптимизиран обект (__slots__): {sys.getsizeof(p2)} bytes")
