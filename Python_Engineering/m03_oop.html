Напреднало ООП, Method Resolution Order и Дескриптори

Анатомия на Python Data Model, алгоритъм C3 Линеаризация за множествено наследяване, атрибутен достъп и създаване на декларативни рамки чрез дескриптори.

3.1. Python Data Model и Специални (Dunder) Методи

Python Data Model е интерфейсът, който позволява на вашите собствени обекти да се интегрират с езика. Чрез имплементиране на специални (dunder) методи, потребителските класове поддържат итерация, итерируеми индекси, итеративни оператори и контекстни мениджъри.

data_model_vector.py
import math

class Vector2D:
    __slots__ = ('_x', '_y')

    def __init__(self, x: float, y: float):
        self._x = float(x)
        self._y = float(y)

    def __repr__(self) -> str:
        return f"Vector2D(x={self._x}, y={self._y})"

    def __abs__(self) -> float:
        return math.hypot(self._x, self._y)

    def __add__(self, other: "Vector2D") -> "Vector2D":
        if not isinstance(other, Vector2D):
            return NotImplemented
        return Vector2D(self._x + other._x, self._y + other._y)

    def __eq__(self, other: object) -> bool:
        if not isinstance(other, Vector2D):
            return False
        return self._x == other._x and self._y == other._y

v1 = Vector2D(3, 4)
v2 = Vector2D(1, 2)
print(v1 + v2)  # Vector2D(x=4.0, y=6.0)
print(abs(v1))  # 5.0

3.2. C3 Linearization & Method Resolution Order (MRO)

При множествено наследяване Python избягва диамантения проблем (Diamond Problem) чрез **C3 Linearization** алгоритъма. Той гарантира запазване на монотонността и локалната последователност на наследяване.

Формулата за линеаризация на клас $C$ с родители $B_1, B_2, \dots, B_n$ е:

$$L(C(B_1 \dots B_n)) = C + \text{merge}(L(B_1), \dots, L(B_n), B_1 \dots B_n)$$

mro_diamond.py
class O: pass
class A(O): pass
class B(O): pass
class C(A, B): pass

# Проверка на MRO
print([cls.__name__ for cls in C.mro()])
# Резултат: ['C', 'A', 'B', 'O', 'object']

3.3. Дълбока Механика на `super()`

Функцията super() не вика директно родителския клас, а връща прокси обект, който делегира метода на **следващия клас в MRO веригата** на екземпляра, от който е извикан.

super_cooperative.py
class Base:
    def __init__(self):
        print("Base.__init__")

class MixinA(Base):
    def __init__(self):
        print("MixinA.__init__ start")
        super().__init__()
        print("MixinA.__init__ end")

class MixinB(Base):
    def __init__(self):
        print("MixinB.__init__ start")
        super().__init__()
        print("MixinB.__init__ end")

class Concrete(MixinA, MixinB):
    def __init__(self):
        print("Concrete.__init__ start")
        super().__init__()
        print("Concrete.__init__ end")

c = Concrete()
# Изход показва как super() преминава през целия MRO: Concrete -> MixinA -> MixinB -> Base

3.4. Протокол за Дескриптори (`__get__`, `__set__`, `__delete__`)

Дескриптор е всеки обект, който дефинира поне един от следните специални методи: __get__(), __set__() или __delete__(). Те прихващат атрибутния достъп на класовете, в които са дефинирани като класови атрибути.

descriptor_basic.py
class BoundedNumber:
    def __init__(self, min_val: float, max_val: float):
        self.min_val = min_val
        self.max_val = max_val

    def __set_name__(self, owner, name):
        self.private_name = f"_{name}"

    def __get__(self, instance, owner):
        if instance is None:
            return self
        return getattr(instance, self.private_name, self.min_val)

    def __set__(self, instance, val: float):
        if not (self.min_val <= val <= self.max_val):
            raise ValueError(f"Стойността {val} трябва да бъде между {self.min_val} и {self.max_val}")
        setattr(instance, self.private_name, val)

class GameCharacter:
    health = BoundedNumber(0, 100)
    mana = BoundedNumber(0, 50)

hero = GameCharacter()
hero.health = 80  # Валидно
# hero.health = 150  # Грешка: ValueError!

3.5. Data Descriptors срещу Non-Data Descriptors

Разликата определя приоритета при търсене на атрибути (Attribute Lookup):

  • Data Descriptor: Дефинира __set__() и/или __delete__(). Има по-висок приоритет от __dict__ на екземпляра!
  • Non-Data Descriptor: Дефинира само __get__() (напр. обикновени методи, @classmethod, @staticmethod). Припокрива се, ако в instance.__dict__ се запише ключ със същото име.

3.6. Чиста Имплементация на `@property` под капака

Декораторът @property е нищо повече от вграден Data Descriptor.

custom_property.py
class PureProperty:
    def __init__(self, fget=None, fset=None):
        self.fget = fget
        self.fset = fset

    def __get__(self, instance, owner):
        if instance is None:
            return self
        if self.fget is None:
            raise AttributeError("Unreadable attribute")
        return self.fget(instance)

    def __set__(self, instance, value):
        if self.fset is None:
            raise AttributeError("Can't set attribute")
        self.fset(instance, value)

    def setter(self, fset):
        return type(self)(self.fget, fset)

3.7. Пълна Иерархия на Достъпа до Атрибут (Attribute Lookup Order)

Когато изпълните obj.attr, CPython следва следния строго определен ред:

  1. Проверява дали attr е Data Descriptor в класа на obj (или неговите родители в MRO).
  2. Проверява дали attr съществува в obj.__dict__.
  3. Проверява дали attr е Non-Data Descriptor или обикновен атрибут в класа на obj (и MRO).
  4. Извиква метода __getattr__(attr), ако е дефиниран в класа.
  5. Хвърля изключение AttributeError.

3.8. Nominal Subtyping (ABC) срещу Structural Subtyping (Protocol)

Характеристика Abstract Base Class (abc.ABC) Protocol Interface (typing.Protocol)
Тип проверка Nominal (Изисква изрично наследяване) Structural (Duck Typing на статично ниво)
Runtime разход Малък (Проверка при извикване/инициализация) Нулев (Ползва се главно от mypy/pyright)
Използва се за Строги йерархии и споделяне на код Гъвкав компонентен дизайн и DI

3.9. Практически Казус: Изграждане на Декларативен ORM Field Validator

orm_field_descriptor.py
class StringField:
    def __init__(self, max_length: int):
        self.max_length = max_length

    def __set_name__(self, owner, name):
        self.name = name

    def __get__(self, instance, owner):
        if instance is None: return self
        return instance.__dict__.get(self.name, "")

    def __set__(self, instance, value):
        if not isinstance(value, str):
            raise TypeError(f"Полето {self.name} трябва да бъде str")
        if len(value) > self.max_length:
            raise ValueError(f"Полето {self.name} надвишава {self.max_length} символа")
        instance.__dict__[self.name] = value

class UserProfile:
    username = StringField(max_length=15)

u = UserProfile()
u.username = "engineering"  # Успешно
# u.username = "this_username_is_way_too_long"  # ValueError!

3.10. Практическа Задача и Интерактивен Куиз

Практическа Задача

Създайте дескриптор @ReadOnlyField, който позволява задаване на стойност на атрибут само веднъж при инициализация (в __init__), а при последващ опит за промяна хвърля AttributeError.

Интерактивен Куиз

Въпрос: Ако клас дефинира атрибут с име, съвпадащо с ключ в instance.__dict__, кой има приоритет, ако атрибутът е Data Descriptor?

A) Data Descriptor има по-висок приоритет и прихваща достъпа.
B) Стойността от instance.__dict__ винаги пренаписва всичко.
C) Хвърля се изключение за конфликт в имената.
