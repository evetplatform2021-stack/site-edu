CPython C-API, C Разширения и Foreign Function Interface (FFI)

Директна интеграция на C/C++ native код с Python, управление на референциите (Py_INCREF/Py_DECREF) на C ниво, преодоляване на GIL и компилация през Cython и pybind11.

7.1. Защо и Кога Използваме C-API?

CPython е написан на C, което позволява директно извикване на C библиотеки или писане на високопроизводителни модули на C/C++ за следните основни цели:

  • Ускорение на критичен код: Заобикаляне на overhead-а на интерпретатора за $10\times - 100\times$ по-бързо изпълнение.
  • Заобикаляне на GIL: Освобождаване на Global Interpreter Lock с Py_BEGIN_ALLOW_THREADS за паралелни изчисления.
  • Интеграция с Legacy C/C++ Библиотеки: Директен достъп до системен софтуер, GPU драйвери или хардуер.

7.2. Менажиране на Референции и GIL на Ниво C

В C няма автоматичен Garbage Collector. Всеки указател от тип PyObject* изисква стриктно проследяване на референциите:

Тип Референция Описание Основни Макроси
New Reference Функцията връща обект с увеличен refcount (+1). Извикващият носи отговорност да го освободи. PyLong_FromLong(), PyUnicode_FromString()
Borrowed Reference Връща указател без промяна на refcount. Обектът се притежава от друг собственик. PyTuple_GetItem(), PyList_GetItem()
Manual Refcount Operations Увеличаване или намаляване на бройката референции ръчно. Py_INCREF(op), Py_DECREF(op), Py_XDECREF(op)

7.3. Написване на C Extension от Нулата

Ето пълен пример за C extension модул (fastmath.c), който дефинира функция fast_add(a, b):

fastmath.c (C Source Code)
#define PY_SSIZE_T_CLEAN
#include <Python.h>

// Функция за събиране на две числа
static PyObject* fastmath_add(PyObject* self, PyObject* args) {
    long a, b;

    // Парсиране на Python аргументи до C long типове ("ll" -> long long)
    if (!PyArg_ParseTuple(args, "ll", &a, &b)) {
        return NULL; // Връща NULL за сигнализиране на изключение
    }

    long result = a + b;
    return PyLong_FromLong(result); // Връща нов PyObject*
}

// Таблица с методи на модула
static PyMethodDef FastMathMethods[] = {
    {"fast_add", fastmath_add, METH_VARARGS, "Бързо събиране на две числа на C ниво."},
    {NULL, NULL, 0, NULL} /* Сигнал за край на таблицата */
};

// Дефиниция на модула
static struct PyModuleDef fastmathmodule = {
    PyModuleDef_HEAD_INIT,
    "fastmath",
    "C Extension Модул за математика",
    -1,
    FastMathMethods
};

// Инициализираща функция (PyInit_)
PyMODINIT_FUNC PyInit_fastmath(void) {
    return PyModuleCreate(&fastmathmodule);
}

За компилиране се използва setuptools скрипт:

setup.py
from setuptools import setup, Extension

module = Extension('fastmath', sources=['fastmath.c'])

setup(
    name='FastMath',
    version='1.0',
    description='C Extension Module',
    ext_modules=[module]
)
# Компилация в терминала: python setup.py build_ext --inplace

7.4. C-FFI Без Компилация: Вграденият `ctypes` Модул

Модулът ctypes позволява зареждане на вече компилирани споделени библиотеки (.so / .dll / .dylib) директно от Python без да е нужен C компилатор на клиента.

ctypes_demo.py
import ctypes
import platform

# Зареждане на стандартната C библиотека (libc)
if platform.system() == "Windows":
    libc = ctypes.cdll.msvcrt
else:
    libc = ctypes.CDLL("libc.so.6")

# Дефиниране на C сигнатурата за puts()
libc.puts.argtypes = [ctypes.c_char_p]
libc.puts.restype = ctypes.c_int

# Извикване на C функцията директно
libc.puts(b"Hello directly from C libc via ctypes!")

7.5. CFFI (C Foreign Function Interface)

cffi е по-модерна алтернатива на ctypes, позволяваща директно поставяне на C декларации в Python код с C parser валидация.

cffi_demo.py
from cffi import FFI

ffi = FFI()

# Дефиниране на C сигнатури
ffi.cdef("""
    int printf(const char *format, ...);
""")

C = ffi.dlopen(None) # Зареждане на стандартното C пространство
C.printf(b"CFFI Execution: %d + %d = %d\n", 10, 20, 30)

7.6. Cython: Хибриден Синтаксис за Висока Скорост

Cython транслира надграден Python код (с C типови декларации cdef) директно до суров C код, генерирайки бърз C extension.

cython_example.pyx
# cython: language_level=3

def compute_sum(int n):
    cdef long long total = 0
    cdef int i
    for i in range(n):
        total += i
    return total

7.7. Съвременни Bindings: `pybind11` и `nanobind`

За C++ разработчиците pybind11 предоставя заглавна библиотека (header-only), която експортира C++ класове и функции към Python с минимален boilerplate и автоматично управление на паметта.

cpp_binding.cpp (pybind11)
#include <pybind11/pybind11.h>

int add(int i, int j) {
    return i + j;
}

PYBIND11_MODULE(cpp_math, m) {
    m.doc() = "pybind11 example plugin";
    m.def("add", &add, "A function that adds two numbers");
}

7.8. Практически Казус: Паралелно Изчисление Без GIL

Освобождаване на GIL при тежки математически изчисления върху масиви от данни, позволяващо на истинските OS нишки да работят 100% паралелно на множество CPU ядра.

nogil_extension.c
static PyObject* heavy_computation(PyObject* self, PyObject* args) {
    long iterations;
    if (!PyArg_ParseTuple(args, "l", &iterations)) return NULL;

    //Освобождаване на GIL
    Py_BEGIN_ALLOW_THREADS

    // Суров C код — работи напълно паралелно без намеса на CPython interpreter!
    double result = 0.0;
    for (long i = 0; i < iterations; i++) {
        result += i * 0.0001;
    }

    // Връщане на GIL обратно преди работа с PyObject
    Py_END_ALLOW_THREADS

    return PyFloat_FromDouble(result);
}

7.9. Практическа Задача и Интерактивен Куиз

Практическа Задача

Напишете малък скрипт с ctypes, който зарежда стандартната функция qsort от C библиотека и я използва за сортиране на C масив от цели числа, създаден през (ctypes.c_int * size)().

Интерактивен Куиз

Въпрос: Какво се случва, ако не повикаме `Py_DECREF()` за нов обект (New Reference), създаден в C extension?

A) CPython автоматично го изчиства при изход от C функцията.
B) Получава се изтичане на памет (Memory Leak), тъй като refcount никога не достига 0.
C) Програмата хвърля Segmentation Fault веднага.
