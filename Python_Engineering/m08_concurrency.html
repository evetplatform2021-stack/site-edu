Concurrency, Parallelism и AsyncIO Архитектура

Паралелизъм срещу съвместност, преодоляване на GIL през процеси, конкурентно синхронизиране с Locks/Semaphores и асинхронно коопериране с Event Loop.

8.1. Сравнителен Модел: Нишки, Процеси и Корутини

Модел Памет Прерапределяне (Switching) Подходящ за Ограничения
Threading Споделена (Shared Memory) Preemptive (от OS) I/O-bound задачи (мрежа, диск) Блокиран от GIL за CPU задачи
Multiprocessing Изолирана (Separate Memory) Preemptive (от OS) CPU-bound задачи (изчисления, ML) Висок Memory Footprint и IPC overhead
AsyncIO Споделена (Single Thread) Cooperative (корутината предава контрол) High-density I/O (хиляди WebSocket/HTTP) Една блокираща функция спира целия Event Loop

8.2. Влиянието на GIL върху Нишките (Thread Safety)

Global Interpreter Lock (GIL) гарантира, че само една нишка изпълнява Python байткод в даден момент. Тъй като превключването на нишки може да се случи между **произволни две байткод инструкции**, операциите, състоящи се от повече от една инструкция (напр. count += 1), **НЕ са атомарни** и изискват изрична синхронизация!

race_condition_demo.py
import threading

counter = 0
lock = threading.Lock()

def unsafe_increment():
    global counter
    for _ in range(100_000):
        # count += 1 се състои от LOAD_FAST, BINARY_OP, STORE_FAST (Race Condition!)
        counter += 1

def safe_increment():
    global counter
    for _ in range(100_000):
        with lock: # Гарантира атомарно изпълнение
            counter += 1

8.3. Модул `threading`: Locks, RLocks, Semaphores & Queues

За безопасна комуникация между нишки стандартната практика е използването на queue.Queue, която е thread-safe по дизайн и имплементира вътрешно заключване.

producer_consumer.py
import threading
import queue
import time

work_queue = queue.Queue(maxsize=10)

def worker():
    while True:
        item = work_queue.get()
        if item is None:
            break
        print(f"Обработен елемент: {item}")
        work_queue.task_done()

# Стартиране на worker нишка
t = threading.Thread(target=worker, daemon=True)
t.start()

for item in range(5):
    work_queue.put(item)

work_queue.join() # Изчква обработката на всички задачи

8.4. Истински Паралелизъм с `multiprocessing` и Shared Memory

За заобикаляне на GIL при CPU-intensive задачи multiprocessing стартира отделни CPython процеси с тяхно собствено заделено пространство в RAM.

shared_memory.py
from multiprocessing import Process, Value, Array

def worker(n, shared_arr):
    n.value = 3.14159
    for i in range(len(shared_arr)):
        shared_arr[i] = i * i

if __name__ == '__main__':
    num = Value('d', 0.0)
    arr = Array('i', range(5))

    p = Process(target=worker, args=(num, arr))
    p.start()
    p.join()

    print(f"Число: {num.value}")
    print(f"Масив: {list(arr)}")

8.5. Абстракция от Висок Клас: `concurrent.futures`

Предоставя единен интерфейс (ThreadPoolExecutor и ProcessPoolExecutor) за асинхронно управление на пулове от нишки или процеси чрез обект Future.

executors_demo.py
from concurrent.futures import ProcessPoolExecutor, as_completed

def heavy_calculation(n: int) -> int:
    return sum(i * i for i in range(n))

if __name__ == '__main__':
    numbers = [10_000_000, 20_000_000, 30_000_000]

    with ProcessPoolExecutor(max_workers=3) as executor:
        # Изпращане на задачи за паралелна обработка
        futures = {executor.submit(heavy_calculation, num): num for num in numbers}

        for future in as_completed(futures):
            input_num = futures[future]
            print(f"Резултат за {input_num}: {future.result()}")

8.6. Механика на `asyncio` Event Loop

asyncio управлява **Event Loop** (цикъл за събития), работещ в една-единствена нишка. Цикълът използва системни механизми като epoll (Linux) или kqueue (macOS) за ефективно изчакване на I/O събития.

8.7. Корутини, Tasks & Futures (`async`/`await`)

Корутините са функции, дефинирани с async def. Ключовата дума await предава обратно контрола на Event Loop докато трае чакането.

async_gather.py
import asyncio

async def fetch_data(id: int, delay: float):
    print(f"Заявка {id} стартира...")
    await asyncio.sleep(delay) # Неблокиращо чакане!
    print(f"Заявка {id} приключи.")
    return {"id": id, "status": "ok"}

async def main():
    # Стартиране на множество корутини паралелно
    results = await asyncio.gather(
        fetch_data(1, 1.0),
        fetch_data(2, 0.5),
        fetch_data(3, 1.5)
    )
    print("Всички резултати:", results)

asyncio.run(main())

8.8. Практически Казус: High-Concurrency Async Crawler

Обработка на хиляди едновременни HTTP заявки с контрол на честотата (Rate Limiting) чрез asyncio.Semaphore.

rate_limited_scraper.py
import asyncio

semaphore = asyncio.Semaphore(5) # Лимит до 5 едновременни заявки

async def download_site(url: str):
    async with semaphore: # Вземане на слот от семафора
        print(f"Сваляне: {url}")
        await asyncio.sleep(1.0) # Симулира мрежова заявка
        return f"Съдържание на {url}"

async def main():
    urls = [f"https://api.example.com/item/{i}" for i in range(20)]
    tasks = [download_site(url) for url in urls]
    results = await asyncio.gather(*tasks)
    print(f"Успешно свалени: {len(results)} страници.")

asyncio.run(main())
