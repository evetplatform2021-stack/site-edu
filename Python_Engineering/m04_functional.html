Функционално Програмиране, Closures, Итератори и Генератори

Анатомия на функциите като First-Class Citizens, вътрешно състояние чрез Cell обекти, замразяване на фреймове при генератори и стрийминг на данни.

4.1. Първокласни Функции и Анатомия на `PyCodeObject`

В Python функциите са обекти от първа класа (First-Class Citizens). Всеки функционален обект е обвивка около компилиран **Code Object** (достъпен чрез атрибута __code__), който съдържа чистия байткод и константите.

code_object_inspection.py
def calculate_tax(amount: float, rate: float = 0.2) -> float:
    base_fee = 5.0
    return (amount * rate) + base_fee

code = calculate_tax.__code__

print("Локални променливи (co_varnames):", code.co_varnames)
print("Константи (co_consts):             ", code.co_consts)
print("Брой аргументи (co_argcount):      ", code.co_argcount)
print("Суров Байткод (co_code):           ", code.co_code[:10]) # Байтове

4.2. Области на Видимост: LEGB Правило и `nonlocal`

При търсене на променлива Python следва стриктното правило **LEGB**:

  1. L (Local): Дефинирани вътре във текущата функция.
  2. E (Enclosing): Дефинирани във влагащи (външни) функции.
  3. G (Global): Дефинирани на ниво модул.
  4. B (Built-in): Вградени имена в езика (len, range, ValueError).

Ключовата дума nonlocal позволява модифициране на променливи от Enclosing обхвата без преминаване към Global.

4.3. Механика на Closures и Cell Обекти

Заграждението (Closure) възниква, когато вътрешна функция реферира променлива от външна функция, дори след като външната функция е приключила изпълнението си. CPython реализира това чрез специални **Cell обекти** в атрибута __closure__.

closure_cells.py
def make_counter(start: int = 0):
    count = start
    def increment():
        nonlocal count
        count += 1
        return count
    return increment

counter = make_counter(10)
print(counter()) # 11
print(counter()) # 12

# Инспекция на Cell обекта в паметта
cell = counter.__closure__[0]
print("Тип на клетката:   ", type(cell))
print("Текуща стойност:   ", cell.cell_contents) # 12

4.4. Напреднали Декоратори и `functools.wraps`

Декораторите са мета-програмистки механизъм за обвиване на функции. За запазване на метаданните (име, docstring, анотации) е задължително използването на @functools.wraps.

advanced_decorator.py
import functools
import time
from typing import Callable, Any

def retry(retries: int = 3, delay: float = 0.1):
    def decorator(func: Callable) -> Callable:
        @functools.wraps(func)
        def wrapper(*args: Any, **kwargs: Any) -> Any:
            last_exception = None
            for attempt in range(1, retries + 1):
                try:
                    return func(*args, **kwargs)
                except Exception as e:
                    last_exception = e
                    time.sleep(delay)
            raise last_exception
        return wrapper
    return decorator

@retry(retries=2, delay=0.05)
def unstable_api_call():
    """Симмулира API извикване"""
    raise ConnectionError("Сървърът не отговаря")

# Метаданните са запазени благодарение на wraps:
print(unstable_api_call.__name__) # 'unstable_api_call'
print(unstable_api_call.__doc__)  # 'Симмулира API извикване'

4.5. Итераторен Протокол (`__iter__` и `__next__`)

Всеки итеруем обект (Iterable) връща Итератор (Iterator) чрез __iter__(). Итераторът трябва да имплементира __next__() и да хвърля изключение StopIteration при изчерпване.

custom_iterator.py
class FibonacciIterator:
    def __init__(self, limit: int):
        self.limit = limit
        self.count = 0
        self.a, self.b = 0, 1

    def __iter__(self):
        return self

    def __next__(self) -> int:
        if self.count >= self.limit:
            raise StopIteration
        val = self.a
        self.a, self.b = self.b, self.a + self.b
        self.count += 1
        return val

for num in FibonacciIterator(5):
    print(num, end=" ") # 0 1 1 2 3

4.6. Генератори и `yield` Механика

Генераторите са специален вид итератори, създадени чрез функции с думата yield. При изпълнение на yield, стек-фреймът на функцията се **замразява** в паметта ($O(1)$ разход на RAM) заедно с локалните променливи, до следващото извикване на next().

4.7. Двупосочна Комуникация: `.send()`, `.throw()` и `yield from`

Генераторите могат не само да излъчват данни, но и да ги приемат динамично по време на изпълнение чрез метода .send().

generator_send.py
def moving_average():
    total = 0.0
    count = 0
    average = None
    while True:
        # Приемане на стойност подадена чрез .send()
        val = yield average
        if val is None:
            break
        total += val
        count += 1
        average = total / count

avg_gen = moving_average()
next(avg_gen) # Инициализация (Prime generator)

print(avg_gen.send(10)) # 10.0
print(avg_gen.send(20)) # 15.0
print(avg_gen.send(30)) # 20.0

4.8. Функционални Примитиви (`functools.partial`, `reduce`, Currying)

За частично прилагане на аргументи се използва functools.partial, позволявайки преизползваемост на логика без наследяване.

partial_example.py
from functools import partial

def power(base: float, exponent: float) -> float:
    return base ** exponent

square = partial(power, exponent=2.0)
cube = partial(power, exponent=3.0)

print(square(5)) # 25.0
print(cube(3))   # 27.0

4.9. Практически Казус: High-Throughput Stream Pipeline

Проблем: Анализ на лог файл с размер 20GB за извличане на IP адреси със статус 500. Стандартното прочитане с readlines() препълва RAM паметта.

Решение: Изграждане на Generator Pipeline (Lazy Evaluation chain) с фиксиран Memory Footprint < 10MB.

stream_pipeline.py
def read_lines(filename: str):
    with open(filename, 'r', encoding='utf-8') as f:
        for line in f:
            yield line

def filter_errors(lines):
    for line in lines:
        if " HTTP/1.1 500 " in line:
            yield line

def extract_ip(error_lines):
    for line in error_lines:
        yield line.split()[0]
