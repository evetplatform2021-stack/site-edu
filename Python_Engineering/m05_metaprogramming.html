Метапрограмиране, Метакласове и Модификация на AST

Създаване на типове по време на изпълнение (Runtime), анатомия на метакласовете, модификация на абстрактни синтактични дървета и изграждане на динамични рамки.

5.1. Динамично Създаване на Класове с `type()`

В Python класовете сами по себе си са обекти от тип type. Когато използвате синтаксиса class MyClass: ..., CPython трансформира дефиницията в извикване на конструктoра type().

Сигнатурата за динамично конструиране е: type(name, bases, dict)

dynamic_class_factory.py
# Традиционна дефиниция:
# class User:
#     role = "admin"
#     def get_role(self): return self.role

# Динамично създаване с type():
def get_role_fn(self):
    return self.role

UserDynamic = type(
    'UserDynamic',                 # Име на класа
    (object,),                     # Базови класове (tuple)
    {'role': 'admin', 'get_role': get_role_fn}  # Атрибути и методи (dict)
)

u = UserDynamic()
print(u.get_role()) # admin
print(type(UserDynamic)) #

5.2. Анатомия на Метакласовете (`__new__` vs `__init__`)

Метакласът е "класът на класа". Той дефинира как се конструира сам по себе си даден клас. За разлика от обикновените класове, в метакласа __new__() създава самия **класов обект**, а __init__() го инициализира.

metaclass_validation.py
class StrictInterfaceMeta(type):
    """Метаклас, който форсира всички методи да имат docstrings"""
    def __new__(mcs, name, bases, namespace):
        for attr_name, attr_value in namespace.items():
            if callable(attr_value) and not attr_name.startswith("__"):
                if not attr_value.__doc__:
                    raise TypeError(f"Методът '{attr_name}' в клас '{name}' няма docstring!")
        return super().__new__(mcs, name, bases, namespace)

class ServiceAPI(metaclass=StrictInterfaceMeta):
    def fetch_data(self):
        """Извлича данни от услугата."""
        return {"status": 200}

    # Подаването на метод без docstring ще хвърли TypeError още при дефинирането!
    # def process_data(self): pass

5.3. Модерен Подход: PEP 487 и `__init_subclass__`

От Python 3.6+ метакласовете често могат да бъдат заменени с __init_subclass__(). Този кука-метод (hook) се задейства автоматично върху родителския клас, когато някой друг клас наследи от него, избягвайки метакласови конфликти.

init_subclass_demo.py
class PluginRegistry:
    plugins = {}

    def __init_subclass__(cls, plugin_name: str, **kwargs):
        super().__init_subclass__(**kwargs)
        cls.plugins[plugin_name] = cls

class AudioPlugin(PluginRegistry, plugin_name="audio_processor"):
    pass

class VideoPlugin(PluginRegistry, plugin_name="video_processor"):
    pass

print(PluginRegistry.plugins)
# {'audio_processor': , 'video_processor': }

5.4. Класови Декоратори срещу Метакласове

Критерий Класов Декоратор (Class Decorator) Метаклас (Metaclass)
Време на изпълнение След като класовият обект е напълно създаден По време на самото конструиране на класа
Наследяване НЕ се предава автоматично на наследниците Автоматично се наследява от всички подкласове
Риск от конфликти Нулев (просто обвива/модифицира обекта) Висок (Multiple Inheritance Metaclass Conflict)

5.5. Персонализация на Пространството от Имена с `__prepare__`

Методът __prepare__() на метакласа се извиква **преди** оценката на тялото на класа. Той връща custom mapping (напр. OrderedDict или обект, следящ за дублирани ключове).

prepare_duplicate_check.py
class UniqueDict(dict):
    def __setitem__(self, key, value):
        if key in self:
            raise KeyError(f"Дублиран атрибут '{key}' не е позволен!")
        super().__setitem__(key, value)

class UniqueMeta(type):
    @classmethod
    def __prepare__(mcs, name, bases):
        return UniqueDict()

# class StrictModel(metaclass=UniqueMeta):
#     x = 10
#     x = 20  # Хвърля KeyError за дублиран атрибут!

5.6. Абстрактно Синтактично Дърво (AST Inspection & Mutation)

Преди CPython да компилира кода до байткод, той изгражда **AST (Abstract Syntax Tree)**. Модулът ast позволява инспекция, анализ и дори трансформации на изходния код в движение през ast.NodeTransformer.

ast_rewrite.py
import ast

source_code = "x = 5 + 10"
parsed_ast = ast.parse(source_code)

print(ast.dump(parsed_ast, indent=2))
# Показва структурата: Module(body=[Assign(targets=[Name(id='x')], value=BinOp(...))])

5.7. Динамично Изпълнение на Код (`exec` и `eval`)

eval() оценява единични изрази и връща стойност, докато exec() изпълнява произволни блокове с Python код. За сигурност винаги трябва да се ограничават глобалните и локалните области от имена (globals/locals).

secure_exec_sandbox.py
user_code = "result = sum([1, 2, 3, 4])"

# Изолирано пространство без достъп до опасни вградени функции
sandbox_globals = {"__builtins__": {"sum": sum, "range": range}}
sandbox_locals = {}

exec(user_code, sandbox_globals, sandbox_locals)
print(sandbox_locals["result"]) # 10

5.8. Практически Казус: Автоматично Регистриращ се Singleton Engine

singleton_meta.py
class SingletonMeta(type):
    _instances = {}

    def __call__(cls, *args, **kwargs):
        if cls not in cls._instances:
            instance = super().__call__(*args, **kwargs)
            cls._instances[cls] = instance
        return cls._instances[cls]

class DatabaseConnection(metaclass=SingletonMeta):
    def __init__(self):
        self.connection_id = "CONN_12345"

db1 = DatabaseConnection()
db2 = DatabaseConnection()

print(db1 is db2) # True -> Един и същ обект в паметта!
